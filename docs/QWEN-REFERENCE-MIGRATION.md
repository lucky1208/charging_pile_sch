# Qwen v1.0.29 参考代码审计与迁移边界

本文记录对 `Qwen-evse-schematic-design-1.0.29` 的静态审计、最小复现实验，以及本平台对其中可用知识的迁移方式。结论不是“整体合并 Qwen 代码”，而是把有价值的功能分类转成受控需求，同时拒绝把未经原始证据复核的板级电路、评分或手绘连接带入工程模型。

## 1. 审计对象与证据等级

审计对象包括 Qwen 包的 `engine/`、`web/js/`、`knowledge/` 和 `SKILL.md`，重点核对：

- `instance-library.js` 的七类功能单元、变体、连接路径及器件文字；
- `circuit-rules.js` 的 15 条规则与拓扑评分；
- `draw-pile.js` 的连接与 SVG 绘制方式；
- `drawing-skill.js` 的几何、网表及检测功能闸门；
- Qwen 说明中声称的 `对比.docx`、图片 126～189 和 `analysis-sN.md` 原始材料。

对 Qwen 目录递归检索后，`对比.docx`、图片 126～189、`analysis-sN.md` 均不存在；现有代码只有对这些材料的文字引用，无法核对原图、页码、局部框、版本、SHA-256 或提取过程。因此本次采用下列证据等级：

| 等级 | 含义 | 能否进入确定性生成 |
|---|---|---|
| `DIRECT_PROJECT_EVIDENCE` | 用户提供的 0823 项目图，可核对设备、端子和连续导线 | 可用于受控系统拓扑，但仍不等于标准认证 |
| `CONTROLLED_STANDARD_OR_CATALOG` | 本平台已有的受控接口、设备类别和符号目录 | 可按适用范围使用 |
| `SECONDARY_EXTRACTION—PRIMARY_EVIDENCE_MISSING` | Qwen 代码中对缺失资料的二次转述 | 只能建立候选知识和待验证功能假设 |
| `CANDIDATE—ENGINEER_REVIEW_REQUIRED` | 未完成原理图、计算、器件数据和试验复核的板级变体 | 禁止自动选型、禁止进入生产 BOM |

直接项目证据仍以本地受控资料 `sch_lib/国标储能充电桩电气原理图0823.svg` 与 `sch_lib/欧标流储充桩电气原理图0823.png` 为准；文件特征、哈希、接口命名冲突和逐线提取保留在不随公共仓库发布的本地证据记录中。公共代码只保留已进入端子级模型、语义 ERC 和回归测试的结构化结论。

## 2. 接受：七类、32 个候选功能单元的分类法

Qwen 的最大价值是把控制板相关问题整理成七类，而不是其主观分数或具体器件值。本平台保留完整分类和 32 个候选 ID，数量核对如下：

| 类别 | 数量 | 候选变体 ID | 本平台处理 |
|---|---:|---|---|
| `psu` 板级辅助电源 | 5 | `self-osc-multi`、`flyback-iso`、`flyback-combo`、`dual-flyback`、`integrated-flyback` | 只读候选；系统级 24 V/12 V 电源已建模，板级实现未决 |
| `diode_det` 车辆二极管存在检测 | 3 | `dual-opamp-hysteresis`、`single-opamp-clamp`、`bjt-level-shift` | 提炼为 CP 接口的功能需求，不选具体电路 |
| `cp_gen` CP 信号发生 | 4 | `opamp-diode-clamp`、`bjt-pushpull-lc`、`opamp-totem`、`opamp-pushpull` | 提炼为 CP 接口的功能需求，不选具体电路 |
| `cp_det` CP 信号检测 | 4 | `follower-peak`、`follower-divider`、`comparator-threshold`、`follower-condition` | 提炼为 CP 接口的功能需求，不选具体电路 |
| `sc_det` 送电前输出回路预检 | 6 | `opto-direct`、`dual-relay-opto`、`bjt-opto`、`bridge-opto`、`diff-opto`、`relay-opto` | 接受“先检后合、测试支路退出”的安全意图，不接受固定实现 |
| `gnd_det` 接地/绝缘检测候选 | 5 | `divider-leak`、`rc-couple`、`diff-amp-iso`、`single-opamp-iso`、`diode-clamp-hw` | 只读候选；不得替代系统级 PE 连续性、RCM 或经认证 IMD |
| `adh_det` 接触器粘连/状态检测 | 5 | `divider-tvs`、`rc-tvs`、`opto-cond`、`relay-opto`、`bridge-opto` | 提炼为逐极反馈和下游带电监测需求，不接受“一个 AD1 标签即完成” |
| **合计** | **32** |  |  |

这些条目落在 `engine/functional-unit-library.js`。每个变体统一标为 `CANDIDATE—ENGINEER_REVIEW_REQUIRED`，并同时设置：

- `automaticSelectionAllowed: false`；
- `fixedValuesApproved: false`；
- 来源状态 `SECONDARY_EXTRACTION—PRIMARY_EVIDENCE_MISSING`。

候选库只供工程师浏览、对比和建立后续验证任务。无论 Qwen 原表写了“最优”“高端首选”“满足国标”、厂家名、出货量还是具体阻容值，都不构成本平台的批准证据。

## 3. 接受：从分类法提炼出的功能需求

### 3.1 CP 发生、采样和车辆二极管检查

本平台接受三项独立功能：CP 波形发生、CP 高阻采样、车辆侧二极管存在检查，但只对**真实物理端子包含 CP 的充电输出接口**适用。CCS1、CCS2、NACS 或 Type 2 等配置是否启用，以受控连接器模板的实际端子为准；GB/T 直流的 `CC1/CC2/S+/S−` 和 CHAdeMO 不能因为名称相似而被强行套用 CP 电路。

三项功能共享同一个可追溯 CP 物理网络，并分别连接控制命令、采样值和二极管判定结果。模型只表达端子及功能关系，不生成运放型号、推挽参数、阈值、钳位值或软件判据。

### 3.2 送电前输出预检

Qwen 的 `sc_det` 名称偏向“短路检测”，但缺失原图不能证明所有 AC/DC 架构采用相同故障判据。本平台把它收敛成更准确的“送电前输出回路预检”：

1. 主功率触点保持断开；
2. 受控测试支路检查连接器下游各载流导体；
3. 测试支路必须确认退出/隔离；
4. 只有预检通过且其他许可条件同时成立，才允许进入待送电状态；
5. 失败或结果不确定时保持全部主触点断开。

阈值、限流、测试电压、超时和诊断覆盖率均为 `PROJECT_VALUE_REQUIRED`，不得从候选分数反推。

### 3.3 接触器逐极反馈与下游粘连监测

本平台把“粘连检测”拆成两种不同证据：接触器机械辅助反馈，以及接触器下游各载流极的电位/带电状态。每个承担安全隔离的接触器都要有精确 `FEEDBACK` 端子和可追溯控制网络；监测单元要覆盖对应输出导体，不能只检查总状态，更不能通过 SVG 中出现 `AD1` 文字就宣告通过。

## 4. 拒绝迁移的实现及可复现实证

### 4.1 拒绝 `draw-pile.js` 的手绘拓扑和第二份 NETS 台账

Qwen 的选型引擎会产生 `R.design`，但 `engine/draw-pile.js` 和 `web/js/draw-pile.js` 中 `R.design` 的词法引用次数均为 **0**。绘图器重新创建自己的 `NETS` 数组，并用固定坐标、位号字符串和循环手写连接。这会形成“模型一份、图面一份、渲染元数据又一份”的多事实源。

代码中已有直接反例：直流正支路的注释写“母线 → 快熔 → 正极接触器 → 枪”，实际线段却接到 `T['DC-']`；直流负支路线段接到 `T['DC+']`。与此同时，随后手工压入 `NETS` 的文字仍声明 `PWR-DC+` 和 `PWR-DC-` 正确。也就是说，网表文字可以“自证正确”，而可见图已经极性互换。

本平台不迁移该绘图器、其 `NETS.push(...)` 或固定坐标。所有连接只能来自 EDEM 精确端点，DrawingIR 和渲染器无权新增、改写或猜测网络。

### 4.2 拒绝主观拓扑分数和“工程可用”结论

Qwen 为每个变体写入 58～92 等固定分，并将规则扣分与候选平均分混合成总分。该分数没有原始试验、失效率、成本条件、适用电压、器件降额、EMC、绝缘配合或版本化权重依据。

最小复现实验进一步证明分数不能作为工程闸门：向 `circuit-rules.review()` 提交若干仅用于命中字符串的器件名称、七个预置高分候选，并明确提交 `nets: []`，返回结果仍为 `score: 95`、`issues: []`、`grade: "工程可用"`。零条连接的“图”不可能被端子级 ERC 接受，因此评分、等级和“最佳变体”均不迁移。

### 4.3 拒绝字符串匹配式 ERC

Qwen 规则主要用器件 `type` 子串、`JSON.stringify(...)` 文本和可选 `units` 字段判断功能存在；网络规则只检查每项是否同时有 `from`、`to`。它不能证明：

- `from/to` 是否为真实存在的精确物理端子；
- DC 正负极、AC 相别、PE、电压域和协议是否匹配；
- 同一端子是否落入多个网络、网络是否连通；
- 预检采样点是否真的在主接触器下游；
- 辅助反馈是否与线圈命令分离；
- CP 发生、采样、连接器和控制器是否位于同一网络。

本平台只接受“这些功能值得检查”的意图，不接受 Qwen 的实现。检查必须遍历 EDEM 的 instance/terminal/net/circuit 引用，并以结构化故障码 fail-closed。

### 4.4 拒绝失效或自证式几何闸门

`drawing-skill.js` 的 G043、G045、G046 先通过 `Number(attribute)` 读取 `stroke`，再把结果与 `'#475569'`、`'#7c3aed'` 比较。`Number('#475569')` 为 `NaN`，目标信号线会被全部跳过，因此“无重叠、避让设备、间距”可以在未实际检查信号线的情况下通过。G045 还使用固定的 `EQ_RECTS` 坐标表，而不是当前图中真实设备 bbox。

G049 只搜索 SVG 是否包含 `SC1 短路检测`、`AD1 粘连检测` 和“检测功能单元”三段文字；这些文字本来就是同一绘图器硬编码生成的，不能证明任何端子或导线存在。以上闸门不迁移。DrawingIR 必须使用结构化线段、设备 keepout、net ID、circuit ID 和 exact endpoint 覆盖做几何及语义审计。

### 4.5 拒绝 Qwen 的 K3/K4/K5 项目位号映射

Qwen `engine.js` 把 K3 写成加热接触器、没有建立真实项目的 K4 直流补电角色，并把 K5 写成充电负接触器。该映射与 0823 直接项目证据冲突：

- K3 是 50 A / 24 V 预充接触器，与 `200 W / 30 Ω` 预充电阻串联；
- K4 是直流补电正极接触器；
- K5 是电池加热接触器。

因此保留当前 0823 受控映射，不复制 Qwen 位号。文件名“国标”与图内 CCS2 端子冲突也继续显式告警，不能以文件名覆盖端子证据。

## 5. 本平台的迁移落点

```text
Qwen 二次提取
  └─ 七类/32 候选（只读、不可自动选择）
        └─ 提炼适用条件明确的功能契约
              └─ EDEM 精确实例/端子/网络/回路
                    └─ ERC 结构与状态机检查
                          └─ DrawingIR 放置/路由/覆盖
                                └─ SVG、DXF 只读渲染
```

### 5.1 EDEM

迁移后的系统模型使用独立受控设备类别：

- `control-pilot-generator`；
- `control-pilot-monitor`；
- `vehicle-diode-detector`；
- `output-precheck-monitor`；
- `contactor-state-monitor`。

它们具有真实功能语义的电源、CP、采样、命令、结果和逐导体监测端子。输出连接器携带接口特定的 `controlContract`；`topology.functionalUnits` 保存实例、网络和回路 ID 的精确交叉引用；`topology.safetyStateMachine` 表达 `ALL_OPEN → PRECHECK → READY → ENERGIZED` 及故障回到全断开状态。未决阈值、时间和板级实现不得被视为通过条件。

### 5.2 ERC

迁移后的 ERC 以接口实际端子和拓扑引用为依据，至少验证：

- CP 功能只在 CP-capable 输出上出现，并且发生、采样、二极管检查的数量及共享物理网正确；
- 每个充电输出各有一个预检和状态监测功能，采样点位于主触点下游并覆盖所有载流导体；
- 安全隔离接触器具有独立反馈，反馈不与线圈命令混接；
- 功能单元引用的 instance/net/circuit 都存在且精确一致；
- 状态机不能绕过 PRECHECK/READY，预检测试支路未确认退出、反馈矛盾或值未决时不得送电。

ERC 证明的是模型内部结构和已编码规则成立，不评价某个候选板级方案是否满足安规、EMC 或器件可靠性。

### 5.3 DrawingIR 与电气符号

五类新增功能以独立电气含义符号进入 IEC 符号目录，并放置于 `SAFETY_DIAGNOSTICS` 功能区；接触器反馈以机械联动辅助触点表达，而不是接在线圈上。每个符号端口锚点继承 EDEM 的 instance/terminal，线路继承 net/circuit，覆盖审计要求每台设备和每条回路均可追溯。符号内部的运放、光耦、晶体管、测试触点等图形用于表达功能原理，不表示已经批准某个 Qwen 候选电路或具体器件值。

## 6. 工程交付边界

本次迁移提高的是“功能不能漏、连接可追溯、送电序列不能被模型绕过”，不是自动完成控制板设计。下列工作仍必须由项目工程师和适用的认证/试验流程完成：

- 从原始原理图、器件数据手册和标准条款建立页码/局部框/版本/哈希证据；
- 确认 CP 电平、阻抗、占空比、故障注入及车辆二极管判据；
- 计算预检电压、限流、阈值、精度、超时、测试支路失效和安全退出；
- 证明接触器每一极的反馈/粘连检测覆盖率及共因失效；
- 完成绝缘配合、爬电距离、电气间隙、器件降额、热设计、EMC、功能安全和型式试验；
- 对项目级 RCM、IMD、PE 连续性、保护整定和选择性作最终确认。

在这些证据完成审批前，32 个板级变体全部保持 **CANDIDATE**；平台不得自动选择、不得把候选器件值写入生产 BOM，也不得用“分数高”“图上有标签”或“生成成功”替代工程批准。
