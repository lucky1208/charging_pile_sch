# EVSE Schematic Design 2.3 — 用户项目证据库、质量规则与在线编辑增量验收

日期：2026-08-30

结论：代码、确定性生成、图模覆盖与第一阶段对象编辑回归通过；工程接受状态仍为 `BLOCKED/REVIEW_REQUIRED`，原因是物理封装脚号、PE/RCM/IMD 功能证据和真实项目逐 PIN 追线尚未关闭。这里的“测试通过”不等于生产图、施工图、标准认证或工程签发通过。

## 1. 本轮可复核产物

- `engine/evidence-library.js`：绑定 `对比.docx`、欧标项目 SVG、国标 60kW 项目 SVG 的来源、页码、文件哈希和观察/推断边界；
- `engine/board-symbol-catalog.js`：29 类板级原生矢量符号，逐 PIN 锚点到符号本体的几何连通审计；符号是 IEC 60617 / GB/T 4728 的项目化重建，不是认证符号数据库；
- `engine/board-circuit-library.js`：7 个代表功能模板、108 条逻辑端口点对点连接和 32 个只读候选拓扑；逻辑 PIN 与物理封装脚号分开，缺失 `pinMap` 显式未决；
- `engine/reference-system-library.js`：两份真实项目的只读 partial trace，共 70 个器件、185 条端点关系和 9 个功能单元；
- `engine/schematic-quality-rules.js`：19 条证据化规则，安全阻断与比较分数分开，证据不够返回 `UNRESOLVED`，不允许用说明文字自证 `PASS`；
- `engine/schematic-editor.js` 与 Web 工作台：选择/检查已有器件、PIN、网络、导线、图示和文字；移动已有器件、已有导线的中间正交段和注释；撤销、重做、恢复自动布局；事务失败回滚并重新执行几何与端点覆盖审计。

`allStructurallyValid: true` 只表示记录内部没有重复 ID、非法引用、未知 PIN、孤儿功能单元或已知网络类别的明显电气域冲突。`allComplete: false` 表示两张图仍不是完整网表，参考实例禁止自动选型、自动接线或作为与原图等价的证明。

关键人工复核结论已经固化为测试：

- 国标枪侧：模块 `DC− → K14 → RS1 → 枪 DC−`；模块 `DC+ → K15 → FU1 → 枪 DC+`；
- 国标辅助电源：T24 是高压 DC→24 V DC/DC，T12 是 24 V→12 V DC/DC；交流入口另有三极交流开关，QF 属于含 MX+OF2 的高压直流辅助链；
- 欧标 PCS 侧：`DC+ → K9 → FU3`，`DC− → K10 → RS1`；
- 欧标枪侧：正侧 `K7 → FU2`，负侧 `K8`。

以上局部追线仍标记为 `ENGINEER_SIGNOFF_PENDING`，厂家端子号、线号和聚合模块内部连接必须以源 CAD、端子表和器件资料复核。

## 3. 防止错误 PASS 的规则加固

本轮新增的反例覆盖包括：

- 双运放/比较器的 V+/V− 必接电源脚不能缺线；
- 预检模板不能只靠“主接触器保持断开”的说明文字通过，必须具有测试继电器线圈/驱动、默认开路、退出开路和失效禁止送电的结构证据；
- 合并整流桥/光耦的粘连检测不能冒充逐安全极独立反馈；
- Y 电容是默认 DNI 的条件装配项，泄漏预算、接地型式和 EMC 试验未关闭时保持 `UNRESOLVED`；
- 板级和系统级 QR-013 分别核对符号目录、PIN 几何和逻辑→物理脚映射，缺物理脚号不再硬编码 `PASS`；
- PE 连续性、RCM/RCD 和 IMD 不再只按器件名称存在性通过，需分别声明连接、检测对象和失效动作；
- 参考网表全部 15 类 `netClass` 使用显式 PIN 电气域白名单，未知类别 fail-closed；
- 圆弧 PIN 几何按实际扫掠角判断，不能把同半径但位于未绘制弧段上的线误判为已连接。

默认国标双枪生成图当前质量画像为 `BLOCKED`，其中 QR-006 缺少完整 PE/RCM/IMD 监测合同，QR-013 有 252 个必需物理脚号未决，QR-019 的真实项目对照仍有 100 个未决项。这是预期的诚实阻断，不影响用户查看方案级草图，但禁止把当前输出称为工程接受图。

## 4. 自动化回归结果

在 Windows、Node.js 24.x 环境执行：

```powershell
npm run build
npm test
```

受控本地证据工作区（客户原图在仓库外部存在）的最终结果：

- 全部测试：`178 / 178` 通过，失败 `0`；
- 高密度参数矩阵：`216 / 216` 通过，失败 `0`；
- 五种标准 × 四种桩型代表组合：`20 / 20` 通过；
- 全套测试耗时：`773705.2077 ms`；其中 216 矩阵耗时 `766256.336 ms`；
- Web bundle 由 26 个 `engine/` 模块确定性重建，源码镜像、缓存哈希和浏览器加载契约通过；
- 29 类板级符号全部通过 PIN→本体几何连通审计；
- SVG、DXF 与 Drawing IR 的设备、网络、回路和精确端点覆盖测试通过。

实际待推送的公共发布工作树还保留了 11 项同源 API 代理测试，并移除了客户项目原图。对该工作树重新执行完整 `npm test` 的结果为：测试 `189`，通过 `188`，失败 `0`，按设计跳过 `1`；216 参数矩阵 `216 / 216` 通过，完整耗时 `588639.9505 ms`，其中矩阵耗时 `583189.7674 ms`。唯一跳过项是“外部原图文件 SHA-256 与证据登记一致”，因为公共仓库不附带原图；同一项在受控本地证据工作区实际读取两张原图并通过，不是以跳过代替本地取证校验。
