这里有两条互补基线，不能混写成同一个“全组合矩阵”：

1. 既有 216 矩阵用于高密度回归直流一体式的功率、枪数、储能和热管理边界：

   ```text
   3 标准（GB / CCS2 / CCS1）
   × 3 功率（60 / 120 / 240 kW）
   × 4 枪数（1 / 2 / 3 / 4）
   × 3 储能模式（无 / DC 耦合 / AC 耦合）
   × 2 热管理（风冷 / 液冷）
   = 216
   ```

2. 独立的标准/桩型契约回归覆盖 `5 接口 × 4 桩型 = 20` 个组合：

   ```text
   GB/T、CCS2、CCS1、NACS、CHAdeMO
   × 直流一体、直流分体、交直流一体、储能移动
   = 20
   ```

216 矩阵的每个组合均执行 EDEM v4.1 构建、ERC、placement、route、Drawing IR exact coverage、全局几何检查、SVG 渲染、drawing audit 和 SVG/DXF 导出闸门；18 个边界组合还实际序列化 DXF。20 个标准/桩型组合逐一验证独立端子级模板与桩型契约，不能将单一额定参数下的 20 个拓扑样本误称为全参数穷举。

## 2. P0 输入与运行时

- RequirementSpec、Web 与 CLI 共用同一枚举、默认值、标准电压联动和 capability gate。
- 五个接口值 `gb`、`eu`、`us`、`nacs`、`chademo` 与四个桩型值 `dc-integrated`、`dc-split`、`ac-dc-combo`、`ess-mobile` 均可选择并进入确定性编译。
- 显式非法数字、布尔、`null`、空串、越界值和未知枚举不再静默回退。
- 低置信度、缺置信度或有未决项时必须人工确认；原始自然语言进入最终 EDEM 来源记录，但只按数据处理。
- `engine/` 是核心实现的唯一源码；`web/js/engine-bundle.js` 由同步脚本生成并以内容哈希校验。

## 3. P1 电气真值、桩型与 ERC

- EDEM v4.1 使用真实导体级端子：L1/L2/L3/N、DC+/DC−、PE、24V/0V、12V/0V、5V/0V和各标准接口针脚均独立。
- 直流分体式明确建模功率柜—终端柜电缆的 DC+/DC−、PE、通信、互锁和 24 V 辅助导体；交直流一体式与储能移动式使用独立拓扑契约，不再回退成直流一体式。
- 储能移动模板保留三电池箱串联、K1–K10、K3 预充支路、PCS、补能输入、模块输出、24/12/5 V 辅助域、输入 EVCC 与输出 SECC、HMI/读卡/语音/风机/路由器等受控设备和连接关系。
- NACS 移动补能使用一个物理共享入口和一个双极、先断后合、默认全断开的 AC/DC 模式选择器。AC/DC 逻辑入口仅为元数据代理，不生成物理符号、网络或自连接回路；ERC 对代理到物理触点的映射、模式互锁和正负极隔离实施精确检查。
- CHAdeMO 的接口辅助 12 V 域保持独立，不被归一化为桩内 12 V 辅助电源。
- 对抗测试在重算 `modelHash` 后验证语义 ERC；极性、相别、电压域、协议、信号角色、预充顺序、串联电池/加热链、熔断节点、输入装配边界及 NACS 代理篡改均会 fail-closed。
- 对适用接口分别建模 CP 发生、高阻采样与车辆二极管检查；每个输出建立接触器下游逐导体预检、逐极反馈/粘连监测和不可旁路的 fail-closed 状态机。7 类/32 个板级候选只读且不得自动选型，专项证据见 `FUNCTIONAL-SAFETY-VERIFICATION.md`。

## 4. P2 IEC 符号、Drawing IR、路由与导出

- 66 个受控 DeviceClass 全部有显式、非 fallback 的 IEC 风格原生矢量符号映射；基础开关、断路器、熔断器、电阻、电池、接地、指示灯、连接器和功能安全诊断单元保留可识别电气图形，而不是统一方框。
- 符号只使用 renderer-neutral 的 line/polyline/circle/arc/rect/text 图元；Drawing IR、SVG 与 DXF 共用符号图元和 trace identity，不嵌入栅格图、base64 或外部 SVG。
- 唯一数据流为 `EDEM v4.1 -> placement/router -> Drawing IR -> SVG/DXF`；渲染器不再依据标量或魔法坐标重建拓扑。
- exact circuit 与 route 一一对应；lane 容量、keepout、异网接触、共线重叠和非法交叉均 fail-closed。
- SVG 以 `data-*` 保存设备、端子、网络、回路、路线和几何哈希追溯。
- DXF 同时使用 `EVSE_IR` XDATA 与 `EVSE-DXF-IR-MANIFEST` 注释元数据；导出 manifest 的追溯方法为 `DXF_XDATA_AND_COMMENT_METADATA`。
- CLI 和 Web 的 DXF 主路径只接受 Drawing IR，不从 SVG 反解析。

## 5. P3 元器件资料工作台

- 路径穿越、Windows 保留设备名、symlink/junction、TOCTOU、输出覆盖、非法 UTF-8、重复 JSON 键和恶意 JS 输入均被阻断。
- 跳级、回退、自审自批、哈希断链、孤立或非规范修订、重算哈希后的语义篡改均被阻断。
- 只有完整历史中的最新 `APPROVED` 修订可导出；`UNKNOWN` 或证据不完整不得批准或自动接线。
- PDF 文本证据按页核验；bbox 与工程结论仍由独立审核人确认。

## 7. 安全与工程边界

本次验收证明的是输入契约、受控目录、端子级模型、已实现 ERC 子集、IEC 风格符号、几何 IR 和导出之间的一致性，不等同于标准符合性或施工可用性。高密度设计目前仍集中在单张自定义幅面，后续需用多页图册、跨页连接器和母线/同网干线合并提升可读性；短路容量、保护整定与选择性、绝缘配合、EMC、温升、型式试验、消防、并网审批和最终版本适用性仍必须由专业人员完成。

P3 的本地 SHA-256 修订链也不等同于数字签名或 WORM。若需要抵抗拥有整个 store 写权限的攻击者，应接入组织级签名、权限分离和不可变审计存储。
