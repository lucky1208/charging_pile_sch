## 1. 审计方法与边界

归档内容被当作不可信参考资料读取，不执行其中的 AI 请求、不使用其中的浏览器密钥存储方式，也不把其网表或质量结论直接并入 EDEM。审计覆盖 `evse-core.js`、`evse-geo.js`、`evse-render.js`、`evse-bom.js`、`evse-ai.js`、`evse-labelfix.js`、`evse-vendor-kb.js`、`index.html` 与 `README.md`；同时以本地静态服务运行默认案例，核对代码宣称与实际诊断结果。

本次采用的是“能力与算法思想迁移 + 重新实现”，不是复制其数据模型。现平台仍以 EDEM v4.1 为唯一电气真值，以 Drawing IR 为唯一几何真值。

## 2. 参考实现真正值得吸收的部分

1. 器件、导线、PIN、标签分别命中和选择，属性面板立即展示对象信息。
2. 器件落点后只重布相连导线，避免每次重画全部页面。
3. 稀疏正交坐标图与 A* 可作为确定性通道/lane 路由失败后的局部兜底。
4. 中间线段可拖动，并尝试推开附近平行线段。
5. 标签使用多个候选位置和代价函数，而不是永远写死在器件中心。
6. 所有导线完成后再统一计算跨线桥和连接点，结果不依赖绘制顺序。
7. 图层开关、键盘撤销/重做、紧凑工作台、对象统计和离线静态运行提升编辑效率。
8. BOM 工作台明确使用 `RFQ_REQUIRED`，这一工程边界是正确的；现平台已有受控 schedule、样例目录状态和 DXF/JSON 导出，继续保留而不另建第二套 BOM 真值。

## 3. 不能照搬的实现及原因

### 3.1 默认图本身没有通过其绘图规则

对参考页面默认案例实测，页面自报：20 段导线穿器件、105 对平行线过近/重叠、2 处对象重叠、131 段导线压文字；但总评仍显示 92/A。说明其分数可以掩盖几何失败，不满足 fail-closed。2.4 不迁移该评分方式，任何几何/端点覆盖违规仍直接拒绝导出或编辑事务。

### 3.2 “拖动时跟线”实际只在松手后重画

参考实现拖动过程中只给器件组加位移，导线留在原位；`pointerup` 后才调用局部 `reroute`。2.4 增加独立预览层：器件移动的每一帧都按精确端点橡皮筋更新所有相连回路，松手后才进入正式寻路事务。

### 3.3 路由存在穿器件兜底

参考路由先尝试固定折线和稀疏 A*，之后逐级放松间距，最终 `FALLBACK` 允许穿器件；这会把“没找到路径”伪装成“已经完成”。2.4 的编辑路由可以降低附加净距以寻找路径，但器件本体永远是硬障碍；无合法正交路径时抛出 `NO_LEGAL_ORTHOGONAL_PATH` 并回滚。

### 3.4 手工导线在移动器件后可能脱 PIN

参考 `reroute` 跳过 `manual` 导线，因此已手调导线连接的器件移动后可能保留旧端点。2.4 不区分“可以脱离模型的手工线”：所有回路始终保存 source/target 的设备、PIN、物理引用和坐标，器件移动必定更新相连端点；最终由 Drawing IR coverage 再证明图等于模型。

### 3.5 挤推只传播一跳且没有最终几何证明

参考 `dragSegment` 只移动一次附近平行中段，不递归检查新碰撞，也不做完整端点/拓扑复核。2.4 把用户拖动的线锁定，把冲突回路加入受影响集合并进行整条正交重布；若新冲突出现则继续扩展受影响集合，最多四轮、最多 64 条，最后必须通过全局几何、交叉后处理和模型 coverage，否则整笔回滚。这是安全的“回路级挤推重布”，仍不是成熟 EDA 的交互式 lane-by-lane 推挤动画。

### 3.6 撤销快照和新增网络不完整

参考历史只保存既有器件位置和导线点，不能可靠撤销新增/删除器件或网络；新拉线在能量域不匹配时还会猜成 `CTL`。2.4 不开放这种危险的猜线功能。撤销/重做保存完整、已验证的 Drawing IR；将来新建/删除网络必须先作为 EDEM 命令完成端子域、网络类和拓扑规则校验。

### 3.7 浏览器密钥和供应商结论不进入现平台

参考 AI 模块把 API Key 放在浏览器/localStorage，并允许 AI 丰富 BOM/供应商链接。2.4 继续只允许同源服务端代理翻译自然语言需求；密钥不下发浏览器，AI 不参与计算、选型、接线、坐标和厂家料号批准。

## 4. 2.4 已落地的集成

- 新增 `engine/schematic-edit-router.js`：器件硬避让、导线非法接触/共线重叠阻断、跨线代价、近线代价、文字软避让、弯折代价、确定性稀疏正交寻路。
- `schematic-editor.js` 升级为 2.0 内核：器件碰撞/出图边界检查、相连回路局部重布、移动器件占用既有导线时的被动回路重布、回路级挤推、路由失败回滚。
- 拖动预览不修改会话：实时显示所有相连导线的新端点与橡皮筋路径；无效器件落点使用红色预览。
- 导线中间段实时预览；端点相邻段继续锁定，不能把线从 PIN 上扯断。
- PIN 属性展示精确网络、回路 ID 与对端 PIN；同一物理端子有多个图形 tap 时用端点坐标区分。
- CAD 图层开关在右侧属性栏始终可达，并与宽屏元件库中的开关同步。
- `Ctrl/Cmd+Z`、`Ctrl/Cmd+Y`、`Ctrl/Cmd+Shift+Z`、`Esc` 接入事务式撤销、重做和拖动取消。
- 每个编辑命令记录几何哈希、自动复核/重布回路 ID、挤推回路 ID 和路由轮次；SVG、DXF、JSON 继续同源。

## 5. 新增验证

自动测试覆盖：

- 障碍物强制绕行与相同输入的路径确定性；
- 移动器件占用无关导线时自动发现并重布；
- 中间段移动导致共线冲突时锁定用户线、重布相邻线；
- 锁定导线进入器件时拒绝且几何哈希不变；
- 预览不改变 revision、history 或 Drawing IR；
- PIN 到网络/回路/对端的解析；
- Web 实时预览、图层、键盘和取消入口契约。

浏览器实测默认 120 kW 国标双枪图：42 个器件、162 条回路；器件实际拖放后重布 13 条回路，Drawing IR 哈希改变且图纸审计保持 `CHECKED`；键盘撤销恢复原哈希；导线中间段实际拖放后几何/ERC 仍通过；浏览器控制台错误为 0。

## 6. 仍未完成的工程 EDA 能力

2.4 明确没有宣称以下能力已经完成：

- 多页层次图、跨页端口、页签和引用坐标；
- 经过 EDEM 审批的新建/删除器件、拉线、断线、网络标签、线束/总线；
- 框选、复制粘贴、对齐、分布、旋转、镜像和位号批量管理；
- 成熟 EDA 的实时递归 lane 推挤、差分/成组约束和后台 Web Worker 增量路由；
- 短路/选择性、线缆、温升、绝缘配合、EMC、型式试验、消防与最终标准适用性证明。

因此 2.4 已从“能拖动但失败就回滚”提升为“实时跟线 + 器件硬避让 + 回路级挤推重布 + 事务证明”，但仍是方案级编译器向工程 EDA 演进的一步，而不是生产签发工具。
