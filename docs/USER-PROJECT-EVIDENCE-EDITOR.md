# 用户项目图纸证据与在线编辑阶段报告

## 1. 本轮目标和证据边界

本轮把三份用户项目资料变成可追溯、可校验、但不会被系统擅自采用的工程知识：

- `对比.docx`：79 页，13 个厂商/项目片段，后 21 页为七类板级功能电路横向比较；
- `欧标充电桩电气原理图.svg`：储能电池、PCS、DC/DC、CCS2、补电入口、控制通信与辅助电源的系统级实例；
- `国标60kW充电桩原理图.svg`：四箱电池、BMS/IMD、交直流补电、国标枪、车联网与辅助配电的系统级实例。

源文件哈希、页码、观察/推断状态登记在 `engine/evidence-library.js`。原图事实、工程推断和已批准设计是三种不同生命周期；平台只允许已批准规则参与确定性选型。

## 2. 从对比文档得到的结构化知识

文档完成 79 页逐页视觉复核后，形成以下七类功能族、32 个候选拓扑。逐页复核完成不等于每张嵌图都已逐导线、逐封装脚号恢复：

1. 板级辅助电源：5 类；
2. 车辆二极管存在检测：3 类；
3. CP 信号发生：4 类；
4. CP 信号检测：4 类；
5. 送电前输出回路预检：6 类；
6. PE/剩余电流/绝缘相关检测：5 类；
7. 接触器状态/粘连检测：5 类。

其中七个代表模板已经重建为器件图，而不是截图：每个器件引用独立符号定义，每条导线都写成 `器件ID:逻辑PIN → 器件ID:逻辑PIN`。当前共 108 条板级逻辑端点连线；双运放/比较器的 V+/V− 也作为必接端子校验。逻辑 PIN 不等同于具体封装脚号；多 PIN 器件缺少受证据支持的 `pinMap` 时会明确报告 `PACKAGE_PIN_MAP_REQUIRED`。器件值、隔离电压、阈值、迟滞、温漂、时序和认证状态仍是项目待决项，模板禁止自动选型。

29 类板级符号使用原生 SVG/Drawing IR 图元重建，覆盖电阻、电容、电感、变压器、共模扼流圈、熔断器、NTC、MOV、GDT、二极管/稳压/TVS、整流桥、BJT/MOSFET、运放/比较器、光耦、继电器线圈与触点、电流互感器、分流器、连接器、测试点和集成电路。这里采用 IEC/GB 项目化表达基线，不声称已经成为某个认证机构的完整 IEC 60617 数据库。

## 3. 两份真实系统图的只读部分追线索引

`engine/reference-system-library.js` 保存两份只读、部分追线参考。当前统计为：

- 70 个系统级器件；
- 185 条器件端点关系；
- 9 个主要功能单元；
- 56 条“端子标注+走线明确”；
- 120 条“走线可见、但仍含聚合端口或未恢复物理线束脚号”；
- 9 条“功能推断、必须复核”；
- 100 个显式未决项，包括未追出的声明端子、功能推断、聚合模块内部端子和待人工签认的局部追线。

这里的 `allStructurallyValid: true` 只表示当前记录没有重复 ID、悬空引用、非法端点或明显电压域冲突；`allComplete: false` 表示它绝不是原图的完整网表。质量规则因此返回 `UNRESOLVED`，不会把结构有效误报为工程 `PASS`。

### 欧标项目主要单元

- 三箱电池串、FU1、K1/K2、K3+预充电阻、RS2、BCU；
- 欧标交流补电座、漏电检测、3P+N 浪涌、KM1/KM2、22kW PCS；
- PCS 直流正侧 K9→FU3、负侧 K10→RS1，以及直流计量和储能母线；
- 30kW DC/DC 正侧 K7→FU2、负侧 K8，以及 CCS2 的 DC+/DC-/PE/CP/PP 和电子锁；
- 4500W-24V、300W-12V、VCU/EVCC/SECC/OCPP、路由器与天线。

### 国标 60kW 项目主要单元

- 四箱电池串联、通信级联和四路加热；
- 电池总正/总负保护、K1 总正、K2 充电正、K3 加热、K4 放电负、K5 充电负；
- H100D 绝缘检测、HAH1BVW 电流传感器和 C10F BMS 主机；
- 直流补电座 DC+/DC-/PE/S2+/S2-/CC2/A2+/A2-；
- 交流枪座和独立三极交流开关、M1~M3 充电模块、直流主回路 QF（含 MX+OF2）、高压 DC→24V 与 24V→12V DC/DC；
- 充电桩主板、VBOX、GPS、路由器、CAN 桥；
- 国标枪负侧 K14→RS1、正侧 K15→FU1，以及 DC+/DC-/PE/S+/S-/A1+/A1-。

这份部分追线索引不是照抄选型表，也不是完整网表。它的作用是：为生成设计提供“应该逐项检查什么”的真实项目能力清单，并把未读清的交叉节点、聚合模块内部端子和线束针号显式保留为未决项。

## 4. 从优劣比较形成的质量规则

质量引擎当前有 19 条证据化规则，并把安全阻断与比较分数分开。QR019 在两份参考仍为 partial trace 时必须返回 `UNRESOLVED/REVIEW_REQUIRED`；结构校验通过不能产生质量 `PASS`。关键规则包括：

- 当前生成设计中的所有已建模导线必须具有精确器件端点和逻辑 PIN；只读参考索引中的未决端点不能借此被冒充为已恢复；
- 图、网表、端子覆盖必须一致；
- 送电前预检不能先闭合主功率接触器；
- 接触器断开反馈/粘连检测必须逐安全极覆盖；
- PE 连续性、RCM/RCD 与 IMD 必须分开建模；
- 高低压测量边界需隔离或完成限能论证；
- 辅助电源的浪涌、共模、差模、母线电容电压裕量应有计算和试验；
- CP 发生/检测需校核带载、短路、钳位、迟滞、容差、温漂和标定；
- 共用短路/粘连前端要做共同原因失效分析；
- N-PE 近零条件下要证明中性线粘连的可观测性；
- Y 电容结论必须和泄漏预算及 EMC 试验绑定；
- 生成设计必须与两份真实项目的功能单元矩阵做适用性对照。

得分只用于比较“已经评估的项目”，任何得分都不能抵消安全阻断项。

## 5. 在线编辑器第一阶段已经完成的能力

浏览器从 Drawing IR 打开一个事务式编辑会话；当前只编辑已存在的 Drawing IR 对象：

- 点击器件，检查位号、类型、坐标和全部 PIN 锚点；
- 点击导线，检查网络、精确起止端点和正交线段；
- 拖动器件，自动重建其端口与相连路由；
- 拖动导线的中间水平/垂直线段；端点相邻线段锁定，防止把线从 PIN 上扯断；
- 移动图示/文字并修改文字内容；
- 撤销、重做、恢复自动布局；
- 每次提交重新计算几何哈希、端点覆盖、碰撞/交叉/keepout；失败则整笔回滚；
- 左侧查看 29 类符号、七个板级模板和两份真实系统参考；右侧检查 PIN→PIN 关系与未决项。

## 6. 尚未完成、不能冒充完成的能力

当前仍是“在线对象编辑第一阶段”，与嘉立创 EDA 等成熟编辑器相比有明确差距：

- 还没有障碍传播式 push-and-shove；当前是移动中间线段并在提交时 fail-closed；
- 还没有多页层次化设计、跨页端口、页间引用和页签导航；
- 还没有从板级模板拖放实例化、自动分配位号和网络合并；
- 还没有框选、对齐、复制粘贴、吸附、交互式加线/删线及差分编辑；
- 还没有完整元器件属性表、封装/厂家料号/额定值规则和审批工作流联动；
- 参考 SVG 的部分交叉点和厂家块内部端子无法只靠扁平矢量可靠恢复，必须补源 CAD、端子表或人工逐线确认。

## 7. 下一阶段建议的工程顺序

1. **多页层次化图纸**：拆分为系统电源单线、每枪功率/控制、储能/BMS、辅助配电、通信拓扑、板级功能单元；建立跨页端口和引用。
2. **可编辑网表操作**：实现从 PIN 拉线、断线、接点、网络标签、总线/线束、位号分配和 ERC 增量检查。
3. **真正的挤推布线**：基于通道和区间图 lane 重新分配，移动导线时传播相邻线段并保证净距，而不是像素网格 A*。
4. **板级模板实例化**：候选拓扑经过工程批准后才能拖入图纸；实例化时要求填写额定值、阈值和验证证据。
5. **认证与数据闭环**：器件数据表、计算书、型式试验、FMEA/FTA 与规则 ID 关联；生成图保留修订、批准和来源哈希。

完成上述阶段后，平台才有资格从“确定性的方案级编译器”继续逼近“工程级在线 EDA”，不能因为界面能拖动就提前宣称生产可用。
