# SchematicForge 平台底座：工程真值、AI 边界与领域扩展

版本：EVSE 示范实现 2.7

> 本文描述已经落地的底座和后续演进边界，不把“自动生成成功”描述为施工可用、标准符合或专业签发。当前输出仍为 `CONCEPT_DRAFT—PROFESSIONAL_REVIEW_REQUIRED`。

## 1. 产品目标

SchematicForge 不是把大语言模型包装成 SVG 画图器，而是面向充电桩、储能、汽车和机器人等设备领域的受控电气设计编译平台。每个领域插件提供自己的需求契约、元器件/端子目录、功能模板、设计规则和证据；公共底座负责不可变工程模型、图册投影、路由、编辑、审查、物料表、审批和可追溯导出。

充电桩是第一个领域示范，但公共底座必须坚持五项不变量：

1. 电气关系只有一个真值源；
2. 图中每根导线都能追溯到真实器件和真实 PIN；
3. SVG、DXF、JSON 是同一 Drawing IR 的不同投影；
4. 几何编辑不能暗改电气拓扑；
5. AI、互联网资料和历史案例只能提出候选，不能自行批准工程结论。

## 2. 权威层级

从高到低的权威链如下：

| 层级 | 数据 | 权限 |
|---|---|---|
| L0 | 经项目批准的标准版本、元器件目录、器件数据表、规则包 | 可成为受控输入；变更必须有人和修订记录 |
| L1 | EDEM 端子级工程模型 | 当前设计的唯一电气真值；实例、端子、网络和回路不可由绘图层重建 |
| L2 | Drawing IR | EDEM 的可追溯几何表达；可移动、重布和添加图注，不能改变 L1 电气身份 |
| L3 | SVG / DXF / JSON / BOM 视图 | 导出与交互视图；必须携带 L1/L2 哈希和追溯信息 |
| L4 | 项目参考图、人工经验、论坛内容、联网检索和模型输出 | 只读证据或 `CANDIDATE`，不得自动提升到 L0/L1 |

平台明确拒绝两套真值：渲染器不能再根据功率和枪数重新“手画”一套隐含网表，BOM 也不能从图中文字反推器件。

## 3. 已实现的数据流

```text
表单 / 自然语言
        │
        ▼
RequirementSpec（规范化、未决项、人工确认）
        │
        ▼
确定性领域编译器（受控目录 + 规则 + 功能模板）
        │
        ▼
EDEM：instance → terminal → net → circuit
        │
        ├───────────────► ERC / 功能安全子规则
        │
        ▼
SchematicDocument（固定六类功能页、跨页连接器对）
        │
        ▼
非权威 Page Projection（高扇出器件可拆为多个图形单元）
        │
        ▼
placement → orthogonal router → crossing post-process → Drawing IR
        │
        ├───────────────► 对象化在线编辑（事务、重布、回滚）
        │
        ├───────────────► SVG
        ├───────────────► DXF R2010 + EVSE_IR XDATA
        └───────────────► JSON 工程包
```

`SchematicDocument` 当前生成六张稳定功能页：

- S01：交流进线、计量与保护；
- S02：功率变换与直流母线；
- S03：充电接口、每枪主回路与控制导引；
- S04：储能簇、BMS 与耦合回路；
- S05：辅助电源、热管理与低压配电；
- S06：控制、通信、检测、联锁与板级功能单元。

没有储能时 S04 仍保留为明确的空功能页，防止页号和交叉引用随配置漂移。页投影绝不复制 EDEM：内部回路只在所属页表示一次，跨页回路在两页各有一个配对连接器，二者共享全局回路 ID、原始两端 PIN、远端页号、图号和端点引用。

高扇出控制器、端子排或母线可以拆成若干图形单元以改善可读性；这些单元全部带 `graphicalRepresentationOf`，没有资格成为新的工程器件。DXF 中 `from/to` 始终记录 EDEM 全局端点，`graphicalFrom/graphicalTo` 单独记录当前页的图形端点。

## 4. 项目级 fail-closed 闸门

导出许可不是一个“综合分数”，而是以下硬条件的合取：

- 需求已确认且没有阻断未决项；
- EDEM 模型校验和端子级 ERC 通过；
- 全局图模覆盖通过；
- 六张功能页均完成编译和页面质量检查；
- 每条内部回路恰好表示一次；
- 每条跨页回路恰好表示两次且连接器成对；
- 每个页面的器件、端子、回路和连接器覆盖完整；
- 路由不穿器件、不越界、无非法短接或未处理交叉；
- 当前编辑事务没有破坏电气身份或几何约束。

任何一项 `BLOCKED` 都禁止工程导出。`REVIEW_REQUIRED` 可以在界面展示和导出概念评审包，但不能被标为生产、施工、IFC、批准或标准合格。视觉美观评分不得覆盖硬错误。

## 5. 在线编辑边界

浏览器编辑器操作 Drawing IR 对象而不是扁平 SVG 像素。当前支持器件/导线/图注/文字命中、选择集、框选、拖动、网格微调、对齐、分布、线段受约束移动、器件硬避让、冲突回路挤推、撤销/重做和属性检查。

页面切换时分别保存该页的 Drawing IR 编辑事务。器件移动后所有相连 PIN 导线实时跟随；落点后重新求解正交路径。如果不存在合法路径，整个事务回滚。编辑器在会话开始时固定 EDEM 的器件、端子、网络、回路和端点身份投影，几何命令不能增删或改接网络。

尚未完成并因此不能宣称成熟 EDA 等价能力的项目包括：经过 EDEM 事务校验的新建/删除器件与网络、从 PIN 交互拉线、总线/线束、复制粘贴、旋转/镜像、层次块复用、多人协作与正式 CAD 原生块/尺寸/报表体系。

## 6. AI 审图

审图采用“双层结论”，防止模型语言覆盖确定性检查：

1. 平台先从 EDEM、ERC、Drawing IR、页覆盖和已批准知识生成稳定的 review case；
2. 用户上传 PNG、JPEG、WebP、SVG、PDF 或 JSON 后，服务端可以调用带视觉能力的模型补充观察；
3. 模型只能返回 `CANDIDATE` 发现、证据位置、置信度和建议验证动作；
4. 平台强制移除模型可能声称的 `APPROVED`、`COMPLIANT` 或“可生产”等权限；
5. 确定性阻断项始终优先显示，最终批准由具名工程人员完成。

审图上下文可以引用人编写的质量规则、项目案例观察、板级模板和系统参考索引，但都携带来源、证据级别和非权威标签。历史图中的相邻位置或可见线段不能被伪装成已经确认的物理 PIN。

服务端限制同源请求、请求体和文件大小，核验 MIME 与文件签名；同源只负责浏览器 CSRF 边界，所有模型 POST 还必须通过统一且不少于 32 字节的站点访问令牌鉴权。模型 API 密钥不进入浏览器，用户访问令牌只保存在当前页面内存。上传内容被当作数据，不能成为指令、代码或规则。

## 7. 工程 BOM 与资料检索

BOM 行只能由 EDEM `instances` 生成，固定显示：

1. 位号；
2. 类别；
3. 设备名称；
4. 型号；
5. 参考推荐厂家；
6. 关键参数；
7. 数量；
8. 说明手册下载。

未批准器件的型号、厂家和手册字段显示“待批准”，状态为 `PART_SELECTION_REQUIRED`。联网搜索可以查找制造商产品页、官方数据表、PCN/EOL 和替代料，但结果只进入带证据 URL 和哈希的 `CANDIDATE`。候选必须在可信 Node.js 边界经过显式 `APPROVE` 决策、审批人、严格时间、依据和 HMAC-SHA256 签名；签名绑定项目 ID、当前 EDEM 哈希和器件实例指纹，浏览器或缺少审批密钥的运行时不能产生/接受批准。即使有效批准记录本身也不能自动改写 EDEM 或生产目录。

这避免了两个常见错误：搜索结果中的经销商同名料被直接写进 BOM，以及模型虚构的 PDF 链接被展示成官方数据表。

## 8. 知识维护任务

仓库包含只读的周期任务，当前计划每周运行并支持人工触发。它做两件事：

- 只读取非空且明确启用的“已批准选型登记册”，检查其 HTTPS 链接、固定 DNS/TLS 目标、重定向、MIME 和料号内容证据；登记册未配置时必须报告 `REVIEW_REQUIRED`，不能以零链接冒充通过；
- 在配置服务端模型时，检索标准修订、制造商 EOL/PCN/召回/替代料和现场工程经验。

网络访问拒绝凭据 URL、非 HTTPS、localhost、私网、IPv4 映射 IPv6 和解析到任一非公网地址的主机；验证后把该公网地址固定到实际 TLS 请求，重定向逐跳重新验证，防止 DNS rebinding/SSRF。响应按字节限额读取。任务只能向 `.verification-output/knowledge-watch` 下的非符号链接路径写入 `CANDIDATE/UNREVIEWED` 报告，不提交代码、不修改生产知识、不更新规则、不自动批准。正确的晋级链是：

```text
CANDIDATE → 人工核对原始证据 → REVIEWED → 具名批准 → APPROVED → 新修订回归 → 发布
```

论坛和用户调试经验可以提供故障模式线索，但在得到制造商、标准、测量或试验佐证以前保持低置信度。

## 9. 领域插件边界

未来扩展储能、汽车或机器人时，领域包应只提供以下声明式能力：

- requirement schema 与产品变体；
- component/connector catalog 及端子定义；
- functional-unit templates；
- topology compiler 与 ERC/设计规则；
- IEC/项目符号映射；
- 受控标准、数据表、项目案例和经验规则。

公共底座继续拥有 EDEM、文控、图册、路由、编辑、审查候选、BOM 候选、审批记录、导出和回归基础设施。领域插件不得直接输出最终 SVG 坐标，也不得绕过公共闸门。

## 10. 2.7 已落地与后续里程碑

2.6 已落地：

- 六页功能图册、页签和跨页引用；
- 高扇出器件的可追溯图形单元；
- 页级 SVG/DXF/JSON 全局 PIN 身份；
- 页级编辑状态和每次编辑后重算的项目级导出闸门；
- 参数、元器件库和属性/PIN/网络检查器组成全宽上方控制台；控制台整体收起、属性区独立收起和全屏均会重新适配图纸；
- 电源、储能、PE、控制和通信图层的线宽/颜色/线型区分；
- AI 上传审图候选管线；
- 八列工程 BOM、联网候选和绑定当前 EDEM/实例指纹的服务端签名审批模型；
- 每周知识证据巡检工作流。

2.7 在此基础上新增：

- 沿实际 circuit 的辅助正负回路、线圈公共端和 PE 同源追踪；
- 最终 SVG 的受限 XML 独立解析与逐段/逐 PIN/逐符号互证，以及真正执行的 G049；
- 最终 DXF `ENTITIES` 与 `EVSE_IR` XDATA 的独立反读；
- 接触器主触点、线圈和反馈的真实端子分离表达；
- 功能区标题保留带、确定性文字 clearance 复核及更紧凑的短标题；
- BOM、逐 PIN 接线、RFQ 和审计 JSON 四项工程附件；
- 折叠态隐藏非绘图详情并居中适页，1280×720 实测绘图区高度达到 535px。

下一阶段应按工程风险排序，而不是按演示效果排序：

1. 完成真实项目参考图剩余物理脚号和未决追线的双人复核；
2. 引入短路电流、保护整定/选择性、线缆载流量与压降、绝缘配合、热和 EMC 计算插件；
3. 建立经过审批的新建/删改电气对象事务及增量 ERC；
4. 建立器件生命周期数据库、制造商身份归一和不可抵赖审批签名；
5. 增加原生 CAD 块、端子图、线缆表、接线表、报表和修订对比；
6. 用匿名化真实工程变更集建立布局可读性、路由稳定性和审图召回率评测。

达到这些里程碑、关闭项目未决项并经过专业签发之前，平台的正确定位仍是“可验证的方案级电气设计编译与编辑底座”，而不是无人复核的自动施工图系统。
